# Named materials and generic substance classes

The 92 current records in `data/substances.json` are broad, stable material classes, **not priced commodity stock identities**. They comprise 75 Desktop-aligned source categories, five Mobile familiar-resource integration parents and 12 approved named-material classification extensions. Do not rename, delete or replace them with familiar resource names: they also classify possible future procedurally discovered materials.

The separate `namedSubstances` manifest collection (`data/named-substances.json`) holds individually identified **physical materials** approved during the MineIT Android economic discovery, including processed materials and strategic exceptions. `genericSubstanceId` links each current named material to an approved broad class. The 12 classification extensions added for previously unmatched materials preserve meaningful distinctions such as refined carbonate salt versus elemental reactive metal, refined precious metal versus generic rare metal, and nonaqueous electrolyte versus aqueous electrolyte solution. Any future null class is an **explicit classification review**, not an implied match.

The 42 already-authored natural resource identities remain authoritative in `mobileResourceDefinitions`. The Directory shows those records under their existing `genericSubstanceId`, without copying them into `namedSubstances`. Named material records use distinct durable `named-substance-*` IDs, preserve discovery provenance and distinguish ordinary stockable materials, non-tradeable spent nuclear waste and on-site concrete. Nuclear Fuel Assemblies and precast construction sections are Parts, not substances; the Vector Exchange Drive is a Machine, not a substance.

**Approved identity does not approve** manufacturing recipes, physical units, market prices, scan/extraction levels, runtime stock integration or ownership rights. Descriptive upstream inputs are not validated quantitative BOMs. Some entries exist in Android as existing manufactured consumables; runtime ID reconciliation remains a separate migration task.

The Directory's Substances tree groups generic classes by archetype, then displays their existing raw Mobile resources and linked named materials as children. Unclassified named materials are visible at archetype level under a conspicuous review heading; they are never silently inserted into a guessed generic class.

`data/` is authoritative; the browser is read-only. MineIT Android retains its older explicitly pinned Universe snapshot until an independently tested migration. Validation must check unique IDs, the parent generic reference, parent archetype agreement and source natural-resource references.

**Source:** MineIT Android discovery catalogues, principally `docs/discovery/processed-*.csv` and `docs/discovery/galaxy-economic-foundation.md` on `kevvy555/MineIT-Android` `develop`. The original Universe material lore remains higher-precedence canon.

## Unified Directory and bulk-review table

The production Directory has **one** Substances navigation entry, grouped by canonical generic substance class. Its child entries include linked 42 named natural resources, 65 named materials and seven biological Food source records (under the Organic archetype). Original stable IDs, mobile occurrence profiles and all other canonical records remain unchanged. The removed duplicate `MineIT Mobile Resources` navigation entry was a second *view* of existing records, not an independent authored dataset.

Click the **Substances** text in the Directory tree (or the header SUBSTANCES link) to open a sortable, filterable bulk-review table. The disclosure arrow expands the tree without changing the detail view. The table contains the 92 generic substance classifications plus 42 natural resources, 65 named materials and seven biological Food records (206 rows at this checkpoint). Generic categories retain their own stable IDs and appear as `Raw substance category`, `Refined substance category`, or one of five `Ontology parent category` rows; they are not copied into the physical resource records. Occurrence profiles are joined as fields, not extra stock rows. The Image column renders only the canonical `image` object owned by that row, so the raw/refined category art appears directly without substituting it for a different named material.

The table has a per-column filter and ascending/descending sort. Its column picker lists every currently present source field, including nested image metadata, provenance, occurrence profile fields and Android reference values; the initial visible columns are a temporary default until a designer selects the final set. Selected columns are remembered for the browser session. Names link back to the ordinary read-only details.

All 206 current table rows own generated catalogue artwork. The 92 generic categories and 65 named materials use canonical assets under `assets/art/universe/substances/`; the 42 natural resources and seven biological Food records retain their canonical resource assets under `assets/art/universe/resources/`. Named-material and classification-extension images follow the established Crops/Emerald icon language while remaining distinct stable-ID assets.

### Android source reconciliation

`game-specs/mineit-mobile/resource-balance-reference.json` is a **reference-only snapshot** of the Android-owned `app/src/main/assets/gameplay/resource-balance.json`, pinning an exact Android `develop` commit and source path. It adds a *view* of Android rarity, occurrence weight, quality bias, base scan level, baseline extraction method/family, reference base price, historical aliases and operational tags. This snapshot is not authored Universe canon and must never become Android's gameplay runtime input; Android remains authoritative for game-specific balance. It has no duplicated names, descriptions or occurrence-zone definitions. The snapshot is referenced by stable canonical resource IDs and validated against the existing 42 natural resources.

Android `ResourceCatalogue.kt` also contains legacy mining tiers, price/proxy values, category multipliers and unlock labels; those values are not merged automatically because their IDs and semantics do not consistently match the canonical 42 resources. Current per-save deposit quality, reserve, generated abundance and market quotes are deliberately excluded. Discovery data contributes provenance and broad approved identities, not invented prices or quantified production recipes.

When extending the bulk table, add new fields to the appropriate canonical entity or game-owned source first. The table is a read-only projection, not another source of truth.

### Bulk-review table workspace and value filters

The Substances table stays in the **right-hand detail pane**, while the left-hand catalogue tree and resizable divider remain visible. **Catalogue tree** returns to the previously selected detail view; opening a named record in the table also opens that normal detail view.

**Choose columns** occupies the **entire width above the table within the right-hand pane**. All 83 current fields appear at once, visibly separated into ten designer-approved categories: Identity & Classification, Properties & Applications, Production & Materials, Game Integration, Governance & Approval, Geological Occurrence, Biology & Agriculture, Game Balancing — Android, Sources & Provenance, and Artwork & Visuals. Category panels sit side by side in a responsive horizontal grid, wrapping into additional rows only when available width requires it. Their checkboxes use two compact columns per panel. Categories are never individually collapsed and have no internal scrollbars. On narrow screens the surrounding detail pane can scroll naturally.

Identity & Classification exposes 11 review concepts rather than schema-specific duplicates: Name, ID, Kind, Archetype, Generic Class, Classification Status, Material Stage, Substance Type, Standard State, Form and Tier. Archetype resolves the record's own dominant archetype or its linked generic class; Generic Class resolves the stable link to a display name; and Material Stage normalizes generic categories and natural resources to `raw` or `refined` while preserving the authored stage on named materials. Biological Food rows remain blank where a physical-material concept does not apply. This is a read-only table projection: canonical `entityType`, `dominantArchetype`, `genericSubstanceId` and `refined` fields remain unchanged in their source records.

Both the overall chooser and **every category** have **Select all** / **Deselect all** controls, affecting only their own scope. Deselect all always retains Name so a user can navigate to an entity. The chooser remembers the selected columns for the browser session and keeps existing per-column sort, text filters, and multi-select value filters. Wide table data still scrolls horizontally when necessary. Adding a new field requires assigning it to a category and extending validation; these groups organise the read-only view, not the underlying canonical JSON.

Every visible column supports a text filter (including numeric comparisons where applicable), click-to-sort, and a **Values** dropdown listing distinct values with checkboxes and an option search. For list-valued fields the dropdown lists **individual values** (e.g. each operational tag or eligible biome), not an arbitrary concatenation. Checking multiple values in one column matches any selected value (OR); combining filters across columns uses AND. The special **(No value)** choice can select entities without a value in that column. With no checkboxes selected, the column remains unrestricted. The column dropdown also has **Choose shown** and **Clear selection**, while the top-level Clear filters resets text and checkbox choices.

The source material, IDs, occurrence rules, and Android reference snapshot are not changed by these UI improvements.
