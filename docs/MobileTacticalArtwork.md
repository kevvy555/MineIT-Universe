# Mobile tactical artwork

`data/mobile-tactical-assets.json` is the Universe-owned catalogue of symbolic tactical presentation assets. It does not replace building identities, catalogue images, the L1–L5 building level images, 3D models, or any 2D/3D generation prompts. Each building symbol links to its existing stable building ID. The compact pylon is a reusable infrastructure symbol rather than a new canonical machine. The rover symbol links to `machine-exploration-vehicle`; the haulage-truck symbol links to the new `machine-haulage-truck` identity. Its engineering, operating limits and catalogue artwork remain unreviewed. Both vehicle concepts are side views, so an in-game heading convention remains to be designed. The five separately layered level badges are presentation graphics, not building variants or save state.

Each record contains the full-size published lossless WebP (`image.key`), original PNG (`originalKey`), a small transparent PNG (`smallImageKey`), exact tactical generation prompt or procedural badge description, creation method and declared pixel dimensions. The reference artwork and its prompt are recorded separately in `generationReference`, where used. Building and vehicle icons are 32 × 32 pixels, the pylon 16 × 16, and badges 13 × 13. Their small images remain unnumbered; game renderers layer a badge when appropriate. Generated originals and the image-generation inputs are retained without claiming separate approval of every individual image.

All originals live under `assets/art/universe/tactical/Originals/`. Published WebPs and small PNGs live outside that folder, so they remain available on GitHub Pages, which excludes originals. The Directory's item details show the linked tactical symbol, its small version, its prompt and reference. Buildings also show linked level artwork and its 2D and 3D prompts, and entity-level 3D model/consistency prompts are displayed when present. Original-image lightboxes fall back to the published WebP on Pages.

Run `python scripts/build-tactical-thumbnails.py` with Pillow to rebuild the small PNGs and WebPs from the retained originals. Run `node validation/validate-universe.mjs` to check coverage, stable references, assets and small-image dimensions. Consumer projects should pin a Universe revision and bundle the small PNGs offline. The sample road/power maps, earlier overhead experiments and map terrain are not part of this collection.

## Tactical texture atlas

`data/manifest.json` exposes `assetBundles.mobileTacticalAtlas` as a repository-root-relative path to the generated atlas JSON. The JSON lists atlas pages, stable tactical asset IDs, linked Universe entity IDs, source paths and SHA-256 values, slot numbers, padded frame rectangles, unscaled sprite rectangles, pixel dimensions, top-left-origin UVs, orientation and centre anchors. The Markdown beside it contains the same slot and coordinate information for review. The 512 × 512 page contains 64 cells of 64 × 64 pixels; the current 32 assets occupy slots 0–31. Source sprites remain 32 × 32, the pylon 16 × 16 and badges 13 × 13, centred without scaling inside transparent cells. Use the sprite rectangle or texel-centre UVs when drawing at native size, not the full padded cell.

Building levels reuse their base symbol; draw the separate level 1–5 badge over the lower-right corner as described by `levelOverlay` in the JSON. The two vehicle symbols are side-view concepts: do not infer or claim a heading rotation convention. The atlas itself has no gameplay logic, Fog of War, renderer, atlas loader or Android integration. A consumer must use the stable IDs and its pinned Universe snapshot; an unknown or missing symbol must be reported rather than silently mapped to a different identity.

Slot assignments are authored in `game-specs/mineit-mobile/tactical-atlas-slots.json`. Preserve existing assignments, append new assets to unused slots and reserve retired slots; never silently renumber or reuse them. The builder rejects missing sources, duplicate IDs and conflicting slots. The default 512-pixel layout supports additional numbered pages. `--size 1024` supports 1024-pixel pages; logical slot IDs stay stable, but page coordinates and UVs must be reread from the regenerated JSON. Do not use whole-atlas mipmaps without an isolation strategy; transparent padding and texel-centre UVs protect ordinary bilinear sampling, not unlimited mip levels.

Rebuild with Python and `pip install -r requirements-tactical-atlas.txt`, then `python scripts/build-tactical-atlas.py`. `python scripts/build-tactical-atlas.py --size 1024 --output <directory>` builds an alternate layout outside the committed default. Run `node validation/validate-tactical-atlas.mjs` for pixel-level coverage, transparency, stable mappings and UV checks; run `python -m unittest discover -s validation -p test_tactical_atlas.py` for deterministic builds, expansion, multi-page and failure cases. The contact sheet and terrain comparisons alongside the atlas are generated review aids; they show native markers and separate level overlays at 24, 32 and 48 pixels over grassland, desert and barren rock. At 24 pixels the smallest level numbers can be hard to read; verify legibility and GPU sampling on device during Android integration.
